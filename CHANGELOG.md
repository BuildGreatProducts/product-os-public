# Changelog

## 1.6.0 — August 2026

**Every filename is now zip-safe.** Uploading ProductOS as a plugin zip through the Claude desktop app failed with "Zip file contains path with invalid characters" — the upload validator rejects paths containing spaces or `&`. Every affected path (47 files and one folder) is renamed; no content moved, nothing was added or removed.

- **The rename pattern:** spaces become hyphens, the numbered prefix drops its dot, `&` becomes `and`. So `1. Product Offer.md` → `1-Product-Offer.md`, `4a. Landing Page.md` → `4a-Landing-Page.md`, `BONUS - Distribution Channels.md` → `BONUS-Distribution-Channels.md`, `4. Scale & Automation Roadmap.md` → `4-Scale-and-Automation-Roadmap.md`, and `design/logo references/` → `design/logo-references/`. Display titles inside the documents keep their human-readable form — only paths changed.
- Every reference across checklists, templates, skills, and guides updated to the new names, including URL-encoded markdown links (`2.%20Growth%20Experiments.md` and friends) and the placeholder patterns (`BONUS-[X]-Onboarding-Best-Practice.md`).
- The `studio-design-prompt-generator` output file is now `productos/design/Design-Prompts.md` (was `Design Prompts.md`) so generated outputs stay zip-safe too.
- **Coached copies:** existing `docs/PLAN.md` files reference the old names; agents match them to the new files without trouble, but plans composed from 1.6.0 onward should use the new names.

## 1.5.0 — July 2026

**The build phase is now Develop, and it gained its quality gates.** The research on AI-built founder apps is blunt — most AI-generated code works and is insecure, and the incidents that killed real apps came from a short list: committed secrets, databases without row-level security, unprotected API routes, missing ownership checks, and secret keys shipped to the browser.

- **Deploy renamed to Develop** across the system: `develop/` folder, `DEVELOP-CHECKLIST.md`, all nine skills `studio-deploy-*` → `studio-develop-*` (precedent: 1.0.0's `studio-build-*` → `studio-deploy-*`), phase prose everywhere (Define → Design → **Develop** → Distribute), and the coach catalog's "Develop route". `docs/DEPLOY.md` keeps its name — it's genuinely the deployment guide. Develop-phase skill H1s normalised to `# Develop: …`.
- **New skill `studio-develop-code-review`** — the deliberate pre-commit pass over uncommitted changes (including new untracked files, where stray secrets land). States the change's intent, reviews across five lenses, verifies every finding against real source (`file:line`, never inference), reports must-fix / consider / **pre-existing** (landmines surfaced without blaming today's diff), and always ends with a verdict: ready to commit or not. Re-reviews report must-fix only — the loop converges. Complements, not duplicates, the build loops' in-flight `/review`.
- **New skill `studio-develop-security-audit`** — full audit of the codebase (or uncommitted changes), ordered by what actually burns founder apps: secrets, RLS/database rules, unprotected routes, IDOR, browser-reachable secret keys, then injection/webhooks/CORS/dependencies/rate-limiting, then headers/CSRF/uploads. Stack-aware (managed auth ⇒ whole categories N/A), verifies every finding to a concrete exploit path, and knows the key-identity rules (anon key public by design; `service_role`/`sk_live_` client-reachable = Critical; RLS-off is the real finding). Produces **`docs/SECURITY-AUDIT.md`**: verdict first, "Do this right now" for leaked credentials (rotate before fixing), a severity-ordered checkbox Fix plan with falsifiable Verify lines a coding agent can execute while the member keeps building, and separate Human-only actions. Never auto-fixes.
- Develop checklist regains its arc with the gates in place: Step 6 code review before commit, Step 9 security audit before go-live (steps renumbered, now 10). The build loops accept the audit's Fix plan as an executable plan file.
- **`setup/CLAUDE.md` + `setup/AGENTS.md` gained "6. Secure by Default"** — the preventive layer wired into every app repo root: no committed secrets, server-side ownership checks, rules on every table from day one, parameterized queries, verified webhooks, no `service_role`/`sk_live_` in the client.
- Skill count 33 → 35.

## 1.4.1 — July 2026

**The Distribute outputs become execution-only.** Students were stalling on documents that carried the whole framework along with the plan.

- `distribute/1-Go-To-Market-Strategy.md` rewritten as a one-page **Go-To-Market Plan**: the customer line, one rule (one channel at a time), and three channel blocks in sequence order — each a one-sentence why, a five-step product-specific "Do this" checklist, "Working =" (number + date), and "If it stalls". All three channels keep full plans; the sequence gates when they start. Gone from the output: the channel menu, the ranked-picks table, Good/Bad blocks, the separate 30-days and What-to-Watch sections (merged into the blocks), and the Sources appendix (now a one-line *Based on:* footer).
- `distribute/2-Growth-Experiments.md` rewritten as a one-page execution list: a two-line header (the metric being moved; the rhythm), **Running now** (1–3 experiments — a plain sentence, a "Do this" checklist, and a Pass = line stating the next move on pass and on fail), and **Up next** (an ordered one-line queue). Effort/impact ratings, the priority guide, and the backlog table are now session material in the skill — the prioritizing still happens, it just doesn't ship.
- Tracker: "Winners & Losers" removed (it duplicated the Decision column and Cumulative Learnings); scale/kill outcomes live only in the tracker, never in the experiments file.
- Both skills gained an explicit output rule — *if a sentence teaches instead of instructs, cut it* — and updated done-state checks ("a reader could execute week one / start experiment 1 tomorrow from this file alone"). Checklist step descriptions and `studio-distribute-scale-automate`'s input references updated to match.

## 1.4.0 — July 2026

**The intake moves to the coach.** Members no longer interview themselves: the coach runs the onboarding call, feeds the transcript into the intake, and hands each new member a copy of ProductOS with their custom programme already inside.

- **`studio-start` removed from ProductOS**, replaced by two pieces:
  - **Coach-side `studio-coach-intake`** — lives in the new private **`coach/`** folder (self-contained, never shipped, excluded from every member copy and anything published). Turns an onboarding-call transcript into the member's `PLAN.md`: extracts where they are against the bundled `ONBOARDING-CALL-GUIDE.md` (the call question set, each block annotated with what it decides), asks the coach about gaps, composes the programme from `MODULE-CATALOG.md` (moved here from the old skill), and adds a **"Verify at setup"** section for anything the coach couldn't see — a condition and its consequence, never a guess.
  - **Member-side `studio-setup`** — the installer: verifies `productos/` sits inside a git repo, wires the root guidelines, gitignores `productos/`, and **adopts the shipped plan** — moves `productos/PLAN.md` to `docs/PLAN.md`, checks the Verify-at-setup items against the actual repo, and annotates (never recomposes — plan revisions come from the coach). Skill count stays 33.
- **Plans ship pre-baked:** the coach's `coach/package-member-copy.sh` builds each member copy — the repo minus `coach/`, with `PLAN.md` seeded at `productos/PLAN.md`. A public copy is the same package with no plan — those users follow the checklists linearly, which the docs now frame as the standard programme (custom plans are a coached-copy perk).
- README, START-HERE, AGENTS.md, checklist preambles, `studio-launch`, and the setup templates re-pointed from the interview framing to the shipped-plan framing.

## 1.3.0 — July 2026

**ProductOS moves in with your product.** There is no separate ProductOS workspace any more: ProductOS is installed inside the app's repository — as a `productos/` folder at the repo root — and it's the first thing set up in the codebase, even before there's any code. From scratch, the repo exists before the product does.

- **One repo, two territories:** `productos/` is the system (checklists, templates, skills, playbooks); the repo-root `docs/` is the product's canon (`PLAN.md`, `PRODUCT.md`, `DESIGN.md` + `DESIGN.html`, `PRD.md`, `ROADMAP.md`, `DEPLOY.md`, `LAUNCHES.md`), living alongside whatever documentation the repo already has. Every path reference across the checklists, templates, and all 33 skills now carries the `productos/` prefix; bundled skill assets are referenced as "in this skill's folder" (also fixing the plugin-install path bug).
- **The Deploy copy ritual is gone.** No more "create a new repo and copy files in" at Step 2. The coding-agent guidelines moved from `deploy/` to **`setup/`** (`setup/CLAUDE.md` + `setup/AGENTS.md`, now opening with a marked ProductOS orientation block) and get wired into the app repo root at setup: copied whole when no root file exists, appended as a `<!-- BEGIN/END PRODUCTOS -->` block when one does — never overwriting.
- **`studio-start` gained a stage-0 setup check:** verifies `productos/` sits inside a git repo (and walks a standalone checkout through creating the app repo and moving in), wires the root guidelines, and adds `productos/` to the repo's `.gitignore` — the materials are licensed to the member, not the public, so they stay uncommitted while the member's outputs remain tracked. Deploy Step 2 became "verify your setup."
- **`studio-define-from-code` reads the surrounding repo directly** — no more asking for a codebase path; the codebase is the repository ProductOS sits in.
- The seven build-phase skills that said "runs inside the product codebase (not in ProductOS)" now say what's true: they run in the app repo — the repository that contains `productos/` — with their ProductOS inputs as defaults rather than "if present in the workspace" hedges (a one-line standalone fallback remains).
- The three Distribute skills' dual paths unified: the standard path reads `productos/`; the bare-codebase branch is now explicitly the standalone fallback for repos without ProductOS.
- All fifteen "search the workspace" locate blocks standardized to look in `productos/` first and never search `node_modules/`, build output, or vendored code; the three build loops now know `docs/PLAN.md` and the checklists are never build plans.
- Internal files removed from the distributable: `PRODUCTOS-REVIEW.md`, `EARLY-WINS-RESEARCH.md`, the Sales Field Guide PDF.

## 1.2.0 — July 2026

The programme now starts with an interview, not a checklist. Members arrive in different places — an idea, a half-built codebase, a live product that needs distribution — and the first cohort showed the linear path fits only the first group. **ProductOS now builds a custom programme per member.**

- New cross-phase skill **`studio-start`** — the intake interview and the new entry point. Reads whatever the member already has (codebase, landing page, existing docs), interviews them about stage, goals, and constraints, then composes a bespoke programme across all four phases and writes it to **`docs/PLAN.md`** (new canonical doc): every checklist step assigned a mode — **Full / Fast-track / Skip / Already-done** — with a reason, a single ordered sequence to work through, and the launches remaining on the signal ladder. Re-running it replans in place. Ships with `MODULE-CATALOG.md`, the composition rulebook encoding every step's dependencies and legal modes.
- Two anchors are hard-coded from cohort experience: **Define is never skipped** (the offer work clarifies what anyone is building, at every stage) and **Distribute is never skipped** (everyone needs distribution) — only their route and timing vary. The middle phases are where programmes genuinely diverge.
- New skill **`studio-define-from-code`** — the Define fast-track for members with an existing product. Extracts draft Product Offer, Customer Persona, and Pricing Strategy from the codebase, live app, or landing page (marked as extracted drafts, gaps named honestly), confirms the load-bearing inferences, then routes into `studio-define-offer-review` (mandatory on this path) and `studio-define-product` as normal. Companion to `studio-design-design-system-from-code`, one phase earlier. Hours instead of days, without skipping the valuable thinking.
- **Plan vs checklists, resolved:** `docs/PLAN.md` governs *which steps apply* to a member; the checklists remain the source of truth for *how each step runs*. A plan can skip work but never a file the sequence still needs — the catalog substitutes the fast-track producer instead. AGENTS.md codifies the split.
- New root **`START-HERE.md`**; README and AGENTS.md re-pointed at `studio-start` as the front door. The linear path survives unchanged as the default programme for from-scratch members — it's exactly what the intake emits for them.
- Checklist preambles now name their fast-track producers and defer to `docs/PLAN.md` when it exists; Deploy Step 1 and the Distribute preamble gained "No `docs/PRODUCT.md` yet?" pointers mirroring the existing Step 3b pattern.
- `studio-launch` now consults `docs/PLAN.md`'s *Launches remaining* — members who arrive with earned rungs start at the right launch, with `docs/LAUNCHES.md` backfilled from their existing signal. Skill count 31 → 33.

## 1.1.0 — July 2026

The program now front-loads a quick win and threads it through all four phases as **the launch ladder**: `reply → conversation → signup → activated user → payment`, tracked in `docs/LAUNCHES.md`.

- **Define slimmed to 5 steps:** Product Offer → Customer Persona → **Pricing Strategy** (new) → **Mini-Launch** (new, ★ the quick win) → PRODUCT.md. The whole phase fits in the first two weeks.
- New template `define/3-Pricing-Strategy.md` + skill `studio-define-pricing` (20–30 min): who pays, one launch price said out loud, real anchors, and the price line the mini-launch carries.
- New template `define/4-Mini-Launch.md` + cross-phase skill **`studio-launch`**: routes by audience access (DM ask / community post / build-in-public post / optional one-pager), drafts the message in the persona's language, timeboxes shipping to 48 hours, and logs every response. **The win is one reply.** Proof is a screenshot of the **live** post or sent DM shared with the cohort — never a draft. Including the price is optional but recommended.
- **Every phase now closes with a relaunch** run by the same `studio-launch` ritual: Design ships "here's what it looks like" (win: one "can I try it?" or signup), Deploy ships the beta invite (win: one activated user), Distribute ships the public launch (win: first payment). Believers first, same channel by default; rungs are targets that trigger a conversation, not gates — the same rung missed twice routes to the Pivot Framework.
- New canonical doc **`docs/LAUNCHES.md`** — the launch log: believers list, one entry per launch, current rung. Created at the mini-launch, read by Business-Strategy, GTM, PRD, and PRODUCT.md synthesis.
- **Business Strategy demoted to an optional deep dive** — now `define/BONUS-Business-Strategy-Deep-Dive.md`, still filled by `studio-define-business-strategy`, recommended when money questions get real (before paid spend, at first revenue).
- **Market Validation removed** — its job (real signal from strangers, pass bars, pivot triggers) is now done live by the launch ladder; the Pivot Framework and Idea Validation Cheat Sheet remain as reference playbooks.
- `studio-define-product` reads the slimmed Define docs + launch log; PRD, GTM, and distribution playbooks re-pointed at Pricing Strategy / Launch Log / the deep dive. Skill count 31 → 32.
- **Product Identity rewritten as the minimum viable brand** — `design/1-Product-Identity.md` now produces six practical decisions instead of brand theory: **Name** (committed, say/spell/search/feel-checked), **Contrarian Belief**, **Tone of Voice**, **Visual Style** (one imagery lane + named references), **Colour Palette** (four real hexes with a competitor-aware rationale), and **Font Pairing** (two free fonts, weights named) — assembled into a one-glance **Brand Card**. Mission and the 12 Jungian archetypes moved to an optional "Going Deeper" tail in the Deep Dive BONUS; the Visual Inspiration appendix is gone (fonts and palette are now first-class sections). `studio-design-identity-creator` rewritten to close every section on a concrete artifact; design-system, prompt-generator, and all other identity consumers re-pointed at the new sections.
- **Design round 2 — identity is words, design system is image-first.** The identity slims to five word-decisions: Name, **Worldview** (new — the pivot-proof conviction above the category), Contrarian Belief, Tone of Voice, Visual Style; Colour Palette and Font Pairing move out. `studio-design-name-review` removed (the identity's light naming pass covers it). **Design System becomes Step 2**, adopting the BuilderOS image-first process: translate a screenshot / Figma file / website you love into `docs/DESIGN.md` (Google-format tokens, source of truth) plus a new self-contained **`docs/DESIGN.html`** style guide rendering every token and component live in the browser — always written together, never drifting. Prompt generator moves to Step 3 and now requires DESIGN.md. Skill count 32 → 31.

## 1.0.0 — July 2026

First packaged release.

- Four complete phases: Define, Design, Deploy, Distribute — each with a checklist runbook, numbered templates, and reference playbooks.
- 31 skills in flat, kebab-case folders matching their skill names (`skills/<name>/SKILL.md`).
- Plugin manifests for all three major agents — installable as a Claude Code plugin (`.claude-plugin/plugin.json`), Codex plugin (`.codex-plugin/plugin.json`), and Cursor plugin (`.cursor-plugin/plugin.json`), all sharing the same `skills/` directory.
- Skill naming unified: `studio-<phase>-*` throughout the deploy phase (`studio-build-*` → `studio-deploy-*`, `feature-finder` → `studio-deploy-feature-finder`, `studio-deploy-checklist` → `studio-deploy-golive`).
- Build strategy unified: agents build straight through all phases, committing at each phase boundary — no PR gates. Security-sensitive phases (auth, payments, user input, data access) get a built-in review pass in all three build loops.
- Market Validation is consistently optional: the checklist marks it recommended-optional and `studio-define-product` proceeds with a noted gap instead of blocking.
- Root `README.md`, `AGENTS.md`, `LICENSE.md`, and this changelog added.
- Internal research data removed from the distributable package.
